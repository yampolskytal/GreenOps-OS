# GreenOps live UI audit — 21 November 2026

Tested the running site at `http://127.0.0.1:8080` in an isolated Firefox profile. Desktop viewport: 1440 × 900; phone viewport: 390 × 844. Opened the CEO, CFO and IT dashboards, Studio, Current Plan, Forecasts, Explore, Data & Reports and Submission. Exercised report preparation before and after adopting the recommendation, and the import form's local file check. No files were submitted to the backend. This was a walkthrough, not a cross-browser or full accessibility certification.

## Fix verification

All seven findings below were addressed. On the updated local site, Firefox showed the official dataset name; the native file input accepted focus and previewed a CI JSONL record. Submission prevented an unadopted suggestion from producing an empty package, offered a route back to the plan, and validated the CSV after explicit adoption. Licence cards showed “SaaS & AI,” connected review cards used owner-review language, and the mobile header displayed “IT Manager” at 390 px. The browser retest stopped at file preview to preserve the active dataset. TypeScript and the frontend and backend test suites passed.

## Original findings (screenshots are before the fixes)

| Priority | Finding and reproduction | Recommended fix / retest |
|---|---|---|
| High | **The export link loses the recommendation context.** In a fresh profile, Current Plan presents seven suggested measures, CHF 116,517 annual savings and 43.5% carbon reduction. Follow **Export submission reports → Package of measures → Check & prepare** without adopting. Submission reports zero selected, 0% savings and offers an incomplete draft. There is no adoption action on that screen. After explicitly adopting the seven measures, the same check reports seven selected and “Ready to submit.” [Plan before export](ui-plan-before.png) · [Result](ui-empty-report.png) | Keep adoption explicit. When only a suggestion exists, label the export action “Adopt a plan before exporting measures,” or provide a link back to adopt it from Submission. An intentionally empty committed plan should still be reportable as empty. |
| High | **The dataset identity undermines the official result.** Open **Data & Reports** after the connected workspace has loaded. The dataset selector reads `demo-v0` alongside 28 sources while the dashboards show the official-case figures. “Latest import” shows 2026-09-06; `backend/frontend_api.py` supplies the analysis `as_of` date for that field, not an import timestamp. [Screenshot](ui-data-settled.png) | Display the active backend dataset name/version; distinguish “Data as of” from the actual import date. In a fresh connected session, the user should be able to tell which dataset will be exported. |
| Medium | **The importer advertises all 28 sources but refuses JSONL.** On **Data & Reports**, drop a file named `ci_pipeline_runs.jsonl`. It immediately says “Not a CSV file” and “Send 0 file(s) for processing.” The organizer supplies this file and `ai_agent_runs.jsonl` in JSONL. The picker also restricts selection to `.csv`. [Screenshot](ui-drop.png) | Accept and validate both formats, or list which files can actually be uploaded and explain how to load the full dataset. |
| Medium | **Keyboard users cannot activate the upload area.** In Data Management, the clickable label has no tab stop (`tabIndex: -1`), and its only file input is `display: none`. A mouse user can open the picker, but the control is absent from sequential keyboard navigation. | Provide a focusable native file control or a labeled button with visible focus. Verify Tab then Enter or Space opens the picker. |
| Medium | **Licence savings appear under Cloud.** Open **Current Plan → Selected measures & evidence**. “Clean up unused SaaS and AI seats” is labeled `licences · Cloud` and “Consolidate duplicate subscriptions” is `subscriptions · Cloud`. The API adapter defaults an unmatched resource to Cloud. This can mislead users looking for the largest software savings. | Map aggregate measures to SaaS, AI or a mixed-service label. Use “Unclassified” for an unknown service. Retest the cards and service filters together. |
| Medium | **Review and readiness language mixes three different decisions.** Connected CFO/IT review cards say “No demo decision.” After adoption, Current Plan says “Saved proposal — not submission-ready”; preparing the same seven measures in Submission says “Ready to submit.” Seven operational reviews remain outstanding. | Distinguish “Saved to this device,” “CSV validated for submission,” and “Owner approval pending.” Use “Report not checked yet” until validation runs; keep demo terminology out of connected review cards. |
| Low | **The phone role selector clips the role name.** At 390 px wide, open the CEO dashboard. The fixed left rail remains, navigation becomes icon-only, and the role name is visibly truncated beside the chevron. This makes role switching harder to discover during a demo. [Screenshot](ui-mobile-ceo.png) | Put a legible role control in the mobile header or navigation drawer. Retest CEO, CFO and IT Manager at 390 px. |

**What worked:** The desktop dashboard showed the expected midpoint targets and budget, with a human-review warning. The phone dashboard stacked its target bars without page-wide horizontal overflow at the tested width. Explicit adoption carried all seven measures into report preparation. The export problem above concerns the transition from a suggestion, not the calculation after adoption.
